# Frontier decision (ORCH-50) — what opens next, and why

**Recommendation: HIERARCHICAL WORMHOLES first** (docs/HIERARCHICAL-WORMHOLES.md),
then learned σ schedules, then a multi-substrate qthe network. Reasoning:

1. The scoreboard says the primitive's value is structural (C1 byte-packing,
   C2 the-only-channel). The one boundary that hurts real consumers is
   provenance-under-congestion (E-Q14 B autopsy: delivery robust, WHO lost).
   Hierarchical tables attack exactly that boundary with the smallest
   mechanism delta (one level, no new physics).
2. Learned σ schedules are now cheap to price honestly: E-Q16's phase table
   shows σ is a pure delivery-latency gain (completion 38→3 over σ 0.25→4,
   bridge metrics invariant). A schedule is therefore a latency policy, and
   its claims are measurable against the phase table — but nothing in the
   corpus currently NEEDS adaptive latency. Wait for a workload.
3. The qthe network (multi-substrate) is jev-garden's problem first (P21
   contract); building it here would duplicate the fleet's own lane.

**On the real/imag split as attention (ORCH-47, investigated):** the split
channel is a SIGN GATE, not a softmax substitute. The confidence cascade
shows where it wins: decisions needing an uncertainty budget (im-mass) and
integer-exact auditability, with evidence that grounds out once decided. It
does NOT win where calibrated mixing is required (softmax's actual job) —
the E-Q15 null is the receipted warning: compounding evidence lost to
max-of-accepted on quality-correlated oracles. Use it as a gate, never as a
mixer.

**Sequencing law (the roadmap's own, honored):** the frontier opens only
after the current claims closed — they are closed (6/6 priced, scoreboard
COMPLETE). The trigger for the hierarchical build: a second live consumer.
