Errata found by the checks themselves

Four, all found live before any claim was written (the falsifier law, pointed at my own deployment):

  • ERRATUM 1 — the first deploy's state hash included the per-tick twin events, which are real telemetry but do not survive a save/load round-trip; the hash was not stable. Fixed: the hash basis is the persisted state only (cells, table, ticks).
  • ERRATUM 2 — the receipt route matched only single-segment keys, so receipts/e_q1_chain.jsonl 404'd. Fixed: all remaining segments join into the key.
  • ERRATUM 3 (r17) — the cron beat's stub.fetch calls defaulted to GET while init/tick need POST; the first HUD was hollow. Found by the P-D check, fixed, re-verified.
  • ERRATUM 4 (r19) — the sidecar's vector ids were field-agnostic (slot-N), so any field's sync could clobber any other's (the 5-minute beat included): a race no retry budget fixes. Fixed: ids namespaced per field, ?field= scopes the lookup, 64 legacy vectors deleted. Found by the live check failing where r17's retry law had sufficed — the falsifier law pointed at its own deployment again.
